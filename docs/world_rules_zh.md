# 服务端世界规则和行为代价

世界由服务器裁决。客户端只提交行动意图；实际能否行动、消耗多少能量、获得多少食物，以及攻击结果都由服务器依据权威世界状态计算。客户端改动本地代码不会修改这些服务端规则。服务器所有者可以调整世界规则。

## 在界面设置

打开服务器控制台，展开“准备下一个世界 → 选择世界设置”。这里可以设置移动、攻击、繁殖及类型改变的消耗、新生能量、进食上限、攻击夺取比例和装甲参数。点击“生成启动方式”，关闭现有服务器后运行生成的命令；这些选项是下一次启动的初始值。客户端的行为阈值只是决策偏好，不是服务器的结算值。

## 编写规则

服务器界面的“进阶：编写世界规则”可编辑和下载 Python 文件。把文件放在服务器可访问的位置，填写其路径并生成启动方式。文件由服务端运行，只应使用可信代码。也可直接运行：

```bash
python -m cellgame server --world-rules my_world.py
```

也可以写在 `server.properties` 里（双击 Start-Server.bat 时使用；路径相对于设置文件所在的目录）：

```properties
world-rules=my_world.py
```

规则文件至少定义 `on_epoch(summary, tick)`，返回一个字典。默认约每 10 个 tick 调用一次；返回的参数会覆盖当前世界设置。

```python
def on_epoch(summary, tick):
    return {
        "food_regrow": 300,         # 地图中补充资源的次数
        "food_regrow_near_cells": 30,
        "metabolism_interval": 10, # 每隔多少 tick 扣除 1 点能量；0 为关闭
        "reproduce_enabled": True,
        "move_cost": 2,             # 每次移动消耗
        "reproduce_cost": 8,        # 父细胞消耗
        "reproduce_min_energy": 10,
        "child_energy": 5,          # 新生细胞初始能量
        "eat_gain": 5,              # 每次最多摄取；仍受当前位置食物限制
        "attack_cost": 3,
        "attack_reward_percent": 50, # 获得被击败细胞能量的百分比
        "change_cost": 1,
        "armor_defense_bonus": 3,
        "armor_move_surcharge": 1,
    }
```

世界参数必须是整数；大部分范围为 0–100，新生细胞能量和繁殖门槛为 1–100。超出范围的规则返回值会被忽略。繁殖时父细胞还必须承担实际繁殖成本。整体移动时，每个成员分别支付移动成本与装甲额外成本。

可选地定义 `on_event(event, world_view)`，返回 `[{"type":"add_food", "x": 10, "y": 10, "amount": 5}]` 或 `[{"type":"set_reproduction", "enabled": False}]`。`world_view.get_region(x,y,w,h)` 提供区域副本。

## 有机体与血缘

悬停在细胞上查看其连接体。仅通过显式连接相连的细胞属于一个有机体；同一玩家的相邻细胞不会自动合并。新生细胞如果与父细胞相连属于生长，否则是一个新的直接后代。断开导致分裂时，保留最多原有细胞的部分继续使用原编号，其他部分成为分裂后代。融合时，贡献细胞最多的原个体保留编号；平局取较小编号，悬浮信息显示融合来源。后代数包括独立繁殖和分裂，记的是直接后代而不是所有后代。编号及历史仅在本次世界运行期间有效。

这些空间连接和边界有助于观察，但它们本身不证明严格的马尔可夫毯。

## 群系和出生

新世界由种子生成连续的草地、森林、沙漠和冻原。它们有不同的初始温度与食物密度；后续食物再生仍按世界规则执行。温度随世界气候变化，群系本身保持不变。新玩家从远离已有其他玩家的候选区域出生；世界拥挤或很小时，不能保证固定安全距离。旧存档或旧版本客户端可能没有群系信息。

服务端本机通过 localhost 打开控制台可观察完整地图；远程观察仍遵循 spectator-map 设置。有限感知客户端只收到被允许感知的群系，未探索区域不显示。服务器主机上的其他本地用户也可访问本机完整地图，请根据需要保护主机。

## 材料与围棋式气规则

世界中有普通食物、浆果、熔岩和尖刺。普通食物按服务端进食上限结算；浆果区有食物时进食会额外获得 2 点能量；熔岩和尖刺上的细胞每 tick 分别损失 5 和 2 点能量。危险区域不会作为新细胞的出生位置。环境材料是独立实现的二维规则，没有使用 Minecraft 的素材文件。

服主可以在“准备下一个世界”中选择“围棋生态”，或使用 `--world-preset go` / 在 server.properties 设置 `world-preset=go`，重启后生效。旧版 `go-rules=on` 与均衡预设会自动迁移为 go；与其他预设或自定义规则同时使用时会报错，需要明确选择。开启时，仅上下左右的同一玩家细胞组成气的计算群，群体与空格正交相邻即有气；世界边界不算气。每一 tick 行动结算后同时移除没有气的群，死亡后的空格不会在同一轮挽救其他无气群。建立细胞连接和带连接的繁殖不能走对角线；移动和不带连接的繁殖仍沿用原规则。这是实时同步结算的围棋式规则，不含标准围棋的落子次序、打劫和自杀判定。关闭时保留原有的八邻域连接。

材料会被发送给可感知该格环境的客户端；受限感知模式的未感知区域不会发送材料。v2 批量观察的 `materials` 与 `tiles` 按行对应：0 普通、1 浆果、2 熔岩、3 尖刺。单细胞接口可读取 `cell.material_here`、`cell.biome_here`，以及 `cell.sense(dx,dy)` 返回对象的 material、biome；不可用时为 None。检查 env_visible 后再使用环境数据。

## 编写行动和生态规则

围棋规则位于 `server/worlds/go.py`，是一个普通的世界规则文件。世界规则可以继承 `server/default_world_rules.py` 中的 `on_epoch`、`on_event`、`after_actions` 和 `before_ecology`，也可以自行替换。`deep_dive.py` 同样是规则文件：它通过 MANIFEST 声明感知和可见性，同时通过代码定义资源行为。

新增可选钩子：

- `filter_actions(intentions, players, world_view, tick)`：返回与动作等长的布尔序列；False 拒绝动作。动作之后仍经过服务端所有权、范围、能量和冲突校验。
- `after_actions(events, world_view, tick)`：成功行动后运行。目前 `events` 提供成功进食事件，包括坐标、细胞 ID、材料；可返回世界命令。
- `before_ecology(world_view, tick)`：行动结算后、代谢和死亡之前运行；可返回世界命令。围棋无气检测使用此钩子。

两个结算钩子返回命令列表。支持 `{"type":"kill", "x":1, "y":2}` 和 `{"type":"adjust_energy", "x":1, "y":2, "amount":-5}`；能量变动为 -100 到 100 的整数，可以附加 `cell_id` 防止作用于已被替换的细胞。所有命令先整体验证再执行，单次命令数量受世界面积限制。`world_view.get_region(x,y,w,h)` 返回副本，`width` 和 `height` 提供世界大小。

这些行动 / 生态钩子时间上限为 100 毫秒；异常、超时或格式错误会停止模拟。on_epoch / on_event 的回调异常或超时则记录日志并丢弃该次结果。超时线程不能被强行终止；规则 Python 代码由服务器进程加载，仍不是安全沙箱，只应运行可信代码。客户端代码从不决定服务器费用或结算。版本及完整阶段顺序见 [核心接口标准](CORE_STANDARD_zh.md)。

当前重构已将无气、连接限制及浆果/熔岩/尖刺的数值和效果移到世界规则代码。基础动作合法性、生成地形、繁殖、移动、碰撞和死亡等仍由引擎提供；这些并非全部已转为可替换的规则。自定义世界如果希望沿用材料效果，可以从默认规则导入对应钩子。
