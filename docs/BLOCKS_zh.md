# 可移动方块

服务器启动时在安全地面上按世界种子生成少量方块；方块独立于地形、食物和细胞。内置围棋世界不生成方块。世界规则文件可以设置 `GENERATE_BLOCKS = False` 关闭初始生成；嵌入内核时可使用 `world.seed_blocks(seed)` 生成，或直接设置 `world.arrays.blocks[y, x]`（0 空、1 木头、2 石头、3 沙子）。

细胞使用现有 MOVE 向八方向移动时，若前方是方块，会将一整条方块链推向同一方向，自己进入原方块位置。MOVE_GROUP 将相连细胞整体移动，并同时推动所有前沿方块链。边界或其他细胞阻挡时整次移动失败；一次最多推动 64 个方块；失败不花费移动能量。推动时每个直接接触方块的细胞在普通移动费用之外支付 `push_cost`，木头、石头和沙子目前的重量相同。细胞不能在方块上出生或繁殖。方块没有重力，不会自主移动，也没有绑定、抓取或背包：实体可通过形状和推动来围住、运输方块，但这不是持有关系。

每 tick 的生态阶段，岩浆地形上的木头消失，沙子转为石头；岩浆地形本身不变。这是一个地形与方块反应的示例，目前还没有方块之间的反应或燃烧传播。世界规则的只读 `WorldView.get_region()` 也可读取 `blocks` 层。

在 radius 或 blanket 感知下，观察 v2 的 `blocks` 是与 `tiles` 对齐的可选 uint8 数组；只有 `env_visible` 为真时，其数值才代表可见信息。Python 单元接口可用 `cell.sense(dx, dy).block` 或 `cell.surrounding()` 的 `neighbor.block`，`None` 表示不可见或服务端未提供此扩展。`is_empty` 仍只表示没有细胞，检查能否繁殖还应检查 `block == 0`。HTTP/stdio 控制器可读取 observation 中的 `blocks` 数组。新版客户端和服务端在 legacy 模式中也提供可选的局部方块观察扩展；连接旧服务器时，方块信息可能为 `None`。旧客户端可以忽略这个扩展。

结果由服务器裁决；竞争或其他行动改变局面后，已接受的移动仍可能在应用时失败，v2 的行动结果会报告 `interrupted`。地图、快照和回放包含方块层；玩家地图只展示或记住所感知的区域。

## 攻击与能量

`cell.attack((dx, dy))` 对准相邻方块时会破坏方块；对准敌方细胞时仍按原战斗规则攻击。破坏当前不产生掉落物、库存或采集资源，也没有硬度和多次破坏进度。方块在本 tick 先被推动离开时，针对其旧位置的攻击会中断且不消耗能量。多个细胞同时攻击同一方块时由服务器按正常争夺规则选出一个行动。

世界可在 `server.properties` 中设置 `move-cost`（普通移动，默认 2）、`push-cost`（推动时额外消耗，默认 0）、`block-attack-cost`（破坏方块，默认 3）以及 `attack-cost`（攻击细胞，默认 3）；取值均为 0–100 的整数。相连实体整体移动时，每个细胞支付移动费用，仅目标格直接有方块的细胞额外支付一次推动费用；其中任何细胞能量不足时整体移动失败。自定义世界的 `on_epoch` 也可以返回下划线形式的键，例如 `{"push_cost": 2, "block_attack_cost": 5}`，从下一次行动起生效。成功破坏会向世界的 `after_actions` 提供 `break_block` 事件，含位置、方块类型和攻击细胞 ID。
